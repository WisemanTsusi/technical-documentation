# Documentation Standard

Every document should answer:
1. What is this?
2. Why does it exist?
3. Who is the audience?
4. What is in scope?
5. What is out of scope?
6. What decisions matter?
7. How is it validated?
8. When should it be reviewed?

Use concrete language, define acronyms, link related decisions/contracts, sanitize examples, date decisions and update documentation with architecture changes.
